### Шаг 1. Определить формат CSV файла

Необходимо на основе потребностей бизнеса определить поля, необходимые в CSV файле
Пример некоторых полей с описанием:

| Поле       | Описание                        |
| ---------- | ------------------------------- |
| id         | Идентификатор товара            |
| name       | Название товара                 |
| price      | Индивидуальная цена для клиента |
| available  | Признак доступности товара      |
| updated_at | Время актуальности данных       |

### Шаг 2. Определиться как файл будет храниться

Необходимо быстро различать файлы для разных клиентов. Рассматривая S3 хранилище, можно:

1)  под каждого агента выделить свой bucket. В этом случае имя файла будет `price_list_{{date}.csv`, а контекст будет задаваться bucket'ом
2) под каждого агента выделить свою директорию внутри bucket. В этом случае имя файла будет `{{ckient_id}}/price_list_{{date}.csv`, а контекст будет задаваться папкой
3) хранить все файлы в общей куче и вынести клиента в имя файла: `pricelist_{{client_id}}_{{date}}.csv`

С учетом того, что нет информации о других файлах для клиентов останавливаемся на варианте 2

### Шаг 3. Реализация скрипта для генерации прайс-листов

В общем виде логика будет следующая:

1) Прочитать конфигурацию
2) Подключиться к PostgreSQL с данными
3) Получить список активных клиентов
4) Для каждого клиента:
   1. Выполнить SQL-запрос с JOIN по products, categories, client_prices
   2. Сформировать CSV-файл.
   3. Загрузить файл в S3
5) Залогировать результаты/возникшие ошибки

### Шаг 4. Реализация Docker-образа

Приложение должно запускаться как CLI-процесс, выполнять выгрузку и завершаться:

```Dockerfile
...
CMD ["python", "-m", "src.price_exporter"]
```

### Шаг 5. Подготовка сущностей K8s

Secret для "чувствительных данных", например, креды БД и S3
ConfigMap для общей информации: IP хоста с БД, имя БД, имя бакета и тд
CronJob для запуска контейнера ежедневно в 6 утра

### Шаг 6. Настройка логирования

Логи контейнера надо писать в Loki

### Шаг 7. Настройка мониторинга и алертов

Продумать метрики и алерты

Примеры метрик:

| Метрика                                      | Описание                                                        |
| -------------------------------------------- | --------------------------------------------------------------- |
| price_export_job_total[result=success\|fail] | Количество запусков джобы. Метка описывает результат выполнения |
| price_export_files_total                     | Количество сгенерированных файлов                               |
| price_export_duration_seconds                | Время выполнения загрузки                                       |

Примеры алертов:

| Условие                         | Триггер                                                                                   | Реакция                                                 |
| ------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Job завершился ошибкой          | price_export_job_total[result=fail] += 1                                                  | Уведомить админа, анализировать логи, ручной перезапуск |
| Job не запустился в 06:00       | price_export_job_total не изменился через некоторое(определяется эмпирически) после 06:00 | Уведомить админа, анализировать логи, ручной запуск     |
| Время выполнения сильно выросло | Дельта по price_export_duration_seconds сильно отличается от прошлых результатов          | Проверить БД                                            |
